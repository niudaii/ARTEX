# 报告归档流程

**task_id**：取自触发本 skill 的「【报告归档任务】task_id=...」消息，后续所有工具调用使用它。

按以下阶段执行报告归档，上一阶段完成并自检后才进入下一阶段。

## 阶段 1 · 读取发现（门槛：必须读全）
调用 list_task_findings(task_id=<task_id>) 读取该任务全部确认漏洞（含漏洞类型/等级/摘要/PoC/证据）。
- 结果被截断或提示更多时继续读全；只凭部分条目归档视为失败。

## 阶段 2 · 过滤误报与定级（渐进加载：评分规则）
先阅读 ${SKILL_DIR}/references/vuln-scoring.md，获取等级定义、调整规则与剔除标准，再逐条判定：
- 剔除：扫描器误报、证据不支持结论的、无实际利用影响的纯信息类条目（以该文件的剔除标准为准）。
- 判定只依据该条目自身证据，不允许臆测。
- 记住被剔除条目的数量与原因概要，写入报告头部说明。
- 同时按该文件的评分规则为每条保留漏洞定级，供阶段 4 使用。

## 阶段 3 · 分组与合并
1. 按域名分组：从每条漏洞的 PoC/证据中提取目标 hostname，按站点归组。
2. 重复合并：同域名 + 同漏洞类型 + 相同/相似端点 → 合并为一条；描述拼接，PoC 取最完整的。
3. 攻击链合并：同域名内多条漏洞构成逻辑利用链（如 RCE → 凭据泄露 → 数据失陷）→ 合并为一条主漏洞，子漏洞以 N.x 层级展开；只合并有因果链的，不机械合并。攻击链按 vuln-scoring.md 的「攻击链评分规则」定级。

## 阶段 4 · 组装归档报告（渐进加载：报告模板）
阅读 ${SKILL_DIR}/references/report-template.md，按其中的报告结构、漏洞模板与排序编号规则组装 Markdown 归档报告。
- 请求/响应包必须来自 finding 证据原文，缺失则注明「证据缺失」，禁止编造。

## 阶段 5 · 写回归档（门槛：必须调用工具）
调用 archive_task_report(task_id=<task_id>, markdown=完整报告) 写回。
- 写回成功即归档完成；之后只回复一行归档结果摘要（归档条目数/等级分布/写回状态），不要输出报告全文。

## 边界
- 只读整理：禁止对任何目标发起请求、攻击、复测或扫描。
- 禁止编造、夸大或润色漏洞事实；凭据类证据保持原样（证据完整性）。
- 过滤后为 0 条时，仍写回一份说明「无可归档漏洞及原因」的简报。
