# 归档报告模板

供报告归档的阶段 4（组装报告）使用。报告为 Markdown，由四部分组成：
标题 → 概览 → 漏洞总结表 → 按域名分组的漏洞正文。

---

## 1. 标题

```
# 渗透测试报告 — {任务描述}
```

任务描述取自触发归档的「【报告归档任务】」消息中的「任务描述」字段；缺失时用 task_id 代替。

## 2. 概览

- 原始发现数 → 归档后数量。
- 剔除说明：被剔除条目数量与原因概要（来自阶段 2 的记录）。
- 等级分布：🔴 严重 / 🟠 高危 / 🟡 中危 / 🟢 低危 各多少条。
- 覆盖域名列表。

## 3. 漏洞总结表

顶格书写，勿缩进：

```
| # | 等级 | 域名 | 标题 | 大概内容 | 修复状态 |
```

- 等级用 emoji：🔴 严重 / 🟠 高危 / 🟡 中危 / 🟢 低危。
- 修复状态默认 ⬜ 待修复。
- 按影响从高到低排列，编号与正文一一对应。

## 4. 漏洞正文

按域名分组，每条漏洞使用统一模板，字段齐全：

```
## N. [等级] 漏洞标题

**漏洞详情**（原始描述）

**请求包**
（http 代码块）

**响应包**
（http 代码块，截断至 1500 字符）

**复现命令**
（bash 代码块）

**漏洞危害**

**修复建议**
（编号列表）
```

- 请求/响应包必须来自 finding 证据原文；缺失则注明「证据缺失」，禁止编造。
- 攻击链主漏洞下的子漏洞以 N.1 / N.2 层级展开，模板相同。
- 凭据类证据保持原样，不做脱敏改写（证据完整性）。

---

## 排序与编号

1. 等级优先：严重 > 高危 > 中危 > 低危。
2. 同等级按实际影响排序：
   RCE/代码执行 > 数据读写篡改 > 大量敏感数据泄露 > 认证绕过 > 越权 > SSRF/内网探测 > 信息泄露。
3. 攻击链置于所属域名组首位。
4. 编号跨域名组全局递增（1、2、3…不按域名组重新计数）。
