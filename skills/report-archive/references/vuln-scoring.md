# 漏洞评分规则

供报告归档的阶段 2（过滤与定级）使用。
原则：**按实际影响定级，证据优先于推测，不夸大不压低**。定级只依据 finding 自身的 PoC/证据；证据无法支撑的影响（如「理论上可读库」但无回显）不得计入，也不得作为升级依据。

---

## 等级定义

### 🔴 严重（满足任一）

- 核心业务系统 RCE / 命令执行 / 代码执行（有 `id`、`whoami` 或等价回显证据）。
- 数据库接管：任意 SQL 执行、DBA 权限、可直接读写核心业务库。
- 核心业务未授权访问：完全无需认证即可操作支付、账户、管理后台等核心数据或功能。
- 大规模敏感数据泄露：≥1 万条个人信息，或服务级关键凭据（AK/SK/证书/秘钥等）批量泄露且可直接接管系统。
- 任意用户账户接管：不依赖用户交互的密码重置逻辑缺陷、验证码绕过等可接管任意用户账户。
- 域名 / 主机接管：DNS 劫持、任意文件写入 getshell 等。
- 远程系统级永久性拒绝服务：投毒/资源长期失效（≥24h），清理或重登后仍可造成拒绝服务。

### 🟠 高危（满足任一）

- 敏感数据泄露：<1 万条个人信息、订单/支付数据、内部敏感文档。
- 垂直越权：低权限账号可执行管理员功能。
- 认证绕过并访问受保护数据：绕过登录/验证码进入受保护资源。
- 任意文件读取/下载：配置文件、源码、凭据文件等。
- SQL 注入（受限）：仅联合/盲注可用，未达 DBA/接管程度。
- 回显 SSRF：可达内网并可读取数据或攻击内网服务。
- 可自动传播的存储型 XSS（蠕虫型）或位于高流量页面的存储型 XSS（管理后台、主站用户可见页面）。
- 客户端远程永久性拒绝服务：清理或重登后仍可造成拒绝服务（重登后可恢复为中危）。

### 🟡 中危（满足任一）

- 水平越权（IDOR）：访问同权限级别其他用户的数据，且涉及敏感信息。
- 重要页面的反射型 XSS 且可自动触发（无需额外点击）。
- 逻辑漏洞：参数/价格/数量篡改等，影响有限且未证明直接资金损失。
- 可进一步利用的信息泄露：源码、含密钥或内网地址的配置。
- 非核心功能的未授权访问。
- 文件上传但未直接 getshell（需结合其他漏洞利用）。
- 测试系统 RCE（不通内网、无真实业务数据）：统一中危。
- 可覆盖/删除线上存储桶文件（NOS/OSS/S3 等生产桶）。
- 绕过限制使用高级服务/获取优惠：基础版越权获取高级版功能、大量重复享受有限制优惠但仅能获取特定非核心资源。

### 🟢 低危（满足任一）

- self-XSS、需受害者主动点击/扫码才触发的反射型 XSS。
- 无敏感数据返回的 JSONP。
- 已知组件版本漏洞但无 PoC 证明当前环境可利用。
- 存储桶文件上传但无法覆盖/删除已有文件：仅能上传新文件时即便是生产桶也定低危；已证明上传内容可在目标域下执行（如存储型 XSS）的除外。
- 间接利用的凭据泄露：如 client_secret 明文泄露于 URL、OAuth 回调走 HTTP（凭据降级），需 MITM 位置或进一步组合才能利用，未证明实际接管账户/系统。
- 登录页 URL 参数引发的 DOM XSS 与 Open Redirect（如 /login 的 url 参数）。
- 匿名可读的监控/调试端点：Prometheus metrics（/metrics）、/debug/pprof 等无法进一步利用（未泄露凭据或可用于接管的信息）。
- 无 TLS 客户端证书校验（双向认证），无法进一步利用时。
- 用户枚举：登录/找回密码/注册等流程可区分账号（手机号/用户名/ID）是否存在，无进一步利用证据。
- 资源消耗型短时拒绝服务：消耗计算/存储资源造成短时间拒绝服务或资源耗尽。
- 利用成本高/变现困难：不能转卖或变现难度大的资源、仅攻击者个人账号获益、新客优惠等实际损失有限的漏洞。
- 其他有证据但无实际利用影响的缺陷。

## 评分调整规则

先按「等级定义」确定基准等级，再按下表一次性调整（多项叠加时合并考虑，最多调 1 级），调整后不超出「严重」上限、不低于「低危」下限：

| 因素 | 调整 |
|------|------|
| 利用需要管理员/高权限凭据前提 | 降 1 级 |
| 需要受害者交互（点击链接/扫码/打开文件） | 降 1 级 |
| 影响核心业务（支付/账户/主数据） | 升 1 级 |
| 仅影响内部测试系统或非生产环境 | 降 1 级 |
| 无法稳定复现 | 降 1 级或忽略 |
| 利用条件苛刻（需特殊账号/权限/极小概率场景） | 降 1 级 |
| 需爆破难度大的字段（≥6 位验证码/密码/认证信息） | 降 1 级或忽略 |
| 业务预期内的可控资损 | 降 1 级或忽略 |

## 攻击链评分规则

- 攻击链整体定级 = 链条**最终达成影响**的等级（如 信息泄露 → SSRF → RCE，按严重定级）。
- 仅当漏洞间存在因果利用依赖时才按链处理；无依赖的漏洞各自独立定级。

## 剔除标准（阶段 2 过滤依据）

满足任一即剔除（各条的除外情形不剔除，按实际影响定级）：

1. **扫描器误报**：工具上报但证据经核对不成立（响应特征不符、payload 未实际执行）。
2. **证据不支持结论**：finding 的 PoC/截图/响应无法支撑其声称的漏洞类型或影响。
3. **无实际利用影响的纯信息类条目**：版本号、banner、Web 指纹（框架/中间件/服务器类型与版本）等纯信息且无法进一步利用。
4. **非本任务目标的发现**：测试对象不在任务范围内的条目。
5. **安全响应头缺失**：HSTS / CSP / X-Frame-Options 等 HTTP 安全响应头缺失，无对应已确认可利用漏洞。
6. **CORS 配置缺陷**：CORS 配置不当且无敏感数据返回；已演示跨域读取敏感数据的除外。
7. **无法进一步利用的报错堆栈**：报错返回堆栈/异常信息，仅暴露类名、方法名、路径等基础设施信息，不含敏感数据。
8. **无法进一步利用的 actuator 泄露**：Spring Boot /health、/info 等端点仅暴露健康状态/版本等基础信息；/env、/heapdump、/configprops 等可泄露凭据的端点除外。
9. **前端加密算法泄露**：仅暴露前端使用的加密算法/模式（算法本身不构成秘密）；同时泄露硬编码密钥/IV 或可据此解密的除外。
10. **SSL/TLS 证书过期**：证书有效期已过但服务仍正常提供加密通信，属配置卫生问题，无进一步利用证据。
11. **无回显 / Blind SSRF**：无法直接获取内部响应。无回显 SSRF 仅通过差异化响应推断端口开放；Blind SSRF 连差异化响应都没有，只能靠带外（OAST/DNSLog）确认请求发出过——两者均无实际数据泄露或内网攻击证据。

不得剔除：

- 等级低但证据真实的漏洞 → 保留，按规则定低危。
- 定级有争议但证据完整的条目 → 保留，按本规则重新定级。
